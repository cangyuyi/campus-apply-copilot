# 企业自建站与垂直门户

> 大厂和行业龙头多数自研网申系统。它们没有统一规律，但**踩坑模式高度相似**。
> 这一篇记录实测过的自建站特征，以及应对没见过的自建站的通用方法。

## 一、通用应对方法

面对没见过的自建站，按这个顺序做：

```
1. domSnapshot 通读页面结构（不要先写选择器）
   ↓
2. 找输入框：列出所有可见 input/textarea 及其 placeholder
   ↓
3. 找按钮：列出所有可见 button 及其文本
   ↓
4. 找容器：观察 CSS 类名前缀，判断是自研还是用了某套 UI 库
   ↓
5. 先用最朴素的方法试：真实鼠标点击 + 真实键入
   ↓
6. 不行再上 React setter / fiber 直调
```

### 第一步永远是 dump 而不是猜

```js
// 页面结构速览
() => ({
  url: location.href,
  title: document.title,
  inputs:  [...document.querySelectorAll('input,textarea')]
             .filter(e => e.offsetHeight > 0)
             .map(e => (e.placeholder || e.type) + '=' + String(e.value).slice(0, 20)),
  buttons: [...document.querySelectorAll('button,[role="button"]')]
             .filter(e => e.offsetHeight > 0)
             .map(e => e.innerText.trim().slice(0, 16)).filter(Boolean),
  sections: [...document.querySelectorAll('[data-nav-id],[data-cy],[class*="block"]')]
             .map(e => e.getAttribute('data-nav-id') || e.getAttribute('data-cy') || e.className.slice(0, 30))
             .slice(0, 20),
})
```

## 二、实测案例库

### 案例 1：金融信息门户（自研，类 Moka 设计系统）

| 项目 | 情况 |
|---|---|
| **识别** | 自有域名，SPA，右上角用户区显示手机号 |
| **表单结构** | 左侧锚点导航 + 右侧长表单，分区明确 |
| **文件上传** | **原生 `change` 事件可用**，简历解析正常 |
| **难点** | `el-upload` 的照片上传口拒绝程序化注入 |
| **解法** | 简历用程序化注入；照片转人工 |
| **额外发现** | 投递后可在「应聘记录」看到性格测试待办 —— **这一步很容易漏，务必检查** |

**教训**：同站点的两个上传口行为可能完全不同（简历口接受、照片口拒绝）。逐个试探，不要因为一个成了就假设另一个也成。

### 案例 2：汽车集团统一校招平台（自研，类 Moka 设计系统）

| 项目 | 情况 |
|---|---|
| **识别** | `campus.<group>.com/campus-recruitment/<brand>/<id>`，`sd-*` 类名 |
| **结构** | 覆盖集团旗下所有品牌，几千个岗位 |
| **筛选** | 城市筛选项是 `sd-Tag` 自定义组件，**不是 checkbox** |
| **搜索** | 搜索框输入后**必须点「搜索职位」按钮**，回车无效 |
| **表单** | 与 Moka 高度相似，`apply-field-` 容器 |
| **利器** | 「同步更新在线简历」勾选后，**下一次投递会自动预填**，省大量时间 |
| **坑** | 自动预填会把「英语水平」同步成 `未参加` —— **必须逐项核对** |

**关键技巧**：

```js
// 城市筛选项（sd-Tag）的正确点法
const anchor = [...document.querySelectorAll('*')]
  .find(e => e.children.length === 0 && e.innerText.trim() === '工作地点');
let sec = anchor;
for (let i = 0; i < 4; i++) sec = sec.parentElement;
const tag = [...sec.querySelectorAll('[class*="sd-Tag-container"]')]
  .find(t => t.innerText.trim() === '杭州市');
tag.click();
```

**搜索框的坑**：`Meta+A` 清空不生效，会**累积关键词**（把「产品」「网联」「AI」拼成「产品网联AI」）。

```js
// ✅ 正确清空方式
const box = page.getByPlaceholder('输入职位关键字');
await box.click();
for (let i = 0; i < 30; i++) await box.press('Backspace');
await box.type(keyword);
await page.getByRole('button', { name: '搜索职位' }).click();   // 必须点按钮
```

### 案例 3：家具品牌自建站（类 Moka）

| 项目 | 情况 |
|---|---|
| **识别** | `join.<brand>.com/campus-recruitment/<brand>/<id>` |
| **表单结构** | 与 Moka 同款 `sd-*` 设计系统 |
| **区块** | 含「项目经验」独立区块（很多平台没有） |
| **难点** | 三级级联「籍贯」只允许选一级；`项目经验` 需要先设「是否有项目经历=是」才出现"添加"按钮 |
| **解法** | 籍贯选到省份即可；项目经历按顺序操作 |

**暴露的问题**：籍贯的值写进了 `input`，但显示层不渲染（显示为空），校验也不报错。

**这类"值对但显示空"的情况**：以 `input.value` 为准，并**提醒用户在预览页留意这一栏**。

### 案例 4：短视频平台校招（自研）

| 项目 | 情况 |
|---|---|
| **识别** | `campus.<company>.cn/recruit/campus/e/#/campus/jobs` |
| **登录** | 手机号 + **图形验证码** + 短信码 |
| **简历页** | 独立的 `/campus/edit-resume`，非常长的表单 |
| **解析质量** | **差** —— 专业识别错误（把 A 专业识别成完全不相关的 B 专业） |
| **专业字典** | 用教育部本科专业目录，**冷门专业搜不到**，需用字段下方的「这里添加」手动补 |
| **坑** | 「这里添加」链接可能属于**别的字段** —— 点错会清空相邻字段的值 |

**操作纪律**：点任何「添加/这里添加/新建」链接前，**先确认它属于哪个字段**（向上找最近的 `.form-item` 容器，看标题）。

### 案例 5：综合门户（自研，`phoenix-*` 无关）

| 项目 | 情况 |
|---|---|
| **识别** | `campus.<company>.com/app/...` |
| **登录** | 手机号 + **身份证号** + 短信码（三要素） |
| **流程** | 四步：投递信息 → 完善简历 → 开放性问题 → 完成投递 |
| **特殊限制** | **该项目只能投递 1 个职位**（HR 处理前可换） |
| **坑** | 第一步「下一步」按钮持续禁用，所有必填项都填了也不解锁 |
| **解法** | 止损让用户刷新页面重进（草稿保留） |

**开放性问题**（4 道，每道 2000 字上限，必填）：

> 1. 你为什么应聘这个岗位？说说你对这份工作的理解，以及它吸引你的地方。
> 2. 你是一个什么样的人？可以聊聊你的性格特点、兴趣爱好、成长经历、当前状态、未来规划，或任何你想分享的内容。
> 3. 请分享一个你自己最近一个月真实在用的产品（App / 功能 / AI 工具皆可），说说它哪个具体设计让你觉得好、或烂，以及你会怎么改。
> 4. 请分享一件最近一年没人要求你做、你自己主动去做的事，以及你为什么想做、做成了什么。

**这类开放题的准备建议**（见 `templates/`）：提前写好 4 类素材，投递时复用改写 ——
① 岗位理解与匹配、② 个人画像与规划、③ 产品批判（选一个你真在用的工具，讲具体设计取舍）、④ 主动性与ownership。

### 案例 6：AI 公司校招（自研）

| 项目 | 情况 |
|---|---|
| **识别** | `hr-jobs.<company>.com/edu/` |
| **登录** | 手机号 + **滑块拼图验证** + 短信码 |
| **附件简历** | 位置在「申请信息」区块，上传后解析质量**好** |
| **表单** | 含 `作品` / `获奖` / `语言能力` / `个人形象` 等区块 |
| **坑** | 解析把实习经历拆错（3 段变 2 段，且只有时间段没公司名） |
| **坑** | 项目经历与工作经历区块混淆（创业项目掉进"工作经历"，但该区块被勾了"没有工作经历"） |
| **作品区块** | 只有「作品名称 + 作品链接」两项 —— **非常适合放 GitHub 开源项目** |

**作品区块的用法**：对于重视"个人作品/开源贡献"的岗位，把 GitHub 仓库逐个列出（名称 + 链接），比写在简历文字里有效得多。

## 三、垂直招聘门户

### 北森招聘门户（`*.hotjob.cn`）

- 职位列表 + 独立表单页
- 列表行可能**不可点**（点击无响应）→ 止损
- 表单走北森老版 `cmp_` 体系 → 见 [beisen.md](beisen.md)

### 51job / 前程无忧（`51job.com`）

- 报名页多为静态 HTML + 简单表单
- `campus.51job.com/<project>/` 形式的专题页
- 岗位列表常分页（`12345下一页尾页`）
- 城市筛选在左侧导航（如 `浙江省 - 杭州`）

### 智联招聘（`zhaopin.com`）

- 表单相对标准，React setter 可用
- 职位列表左侧筛选，右侧列表

### 问卷星 / 金数据 / 腾讯文档

部分公司（尤其国企、事业单位）用**在线表单工具**收集简历：

| 工具 | 域名 | 特征 |
|---|---|---|
| 问卷星 | `v.wjx.cn` | 一页到底的调查问卷式 |
| 金数据 | `jsj.top` | 同上 |
| 腾讯文档 | `docs.qq.com/form` | 同上 |

**特点**：字段是调查问卷式的，没有简历解析。**必须全手工填**。

**判断**：如果打开后看到的是"调查问卷"而不是"招聘申请表"，就是这类 —— 直接按字段逐项填，没有捷径。

## 四、自建站的六类共性问题

### 1. 职位列表行不可点

**现象**：职位标题存在，点击无响应，没有 `<a>` 标签。

**排查**：

```js
const el = [...document.querySelectorAll('*')]
  .find(e => e.innerText.trim() === '目标岗位名');
let q = el, path = [];
for (let k = 0; k < 6 && q; k++) {
  path.push(q.tagName + '.' + String(q.className).slice(0, 40) + (q.getAttribute('href') || ''));
  q = q.parentElement;
}
console.log(path);   // 看有没有 <a href>
```

- 有 `<a href>` → 直接 `goto` 该 URL
- 无 `<a href>` → 试 `dispatchEvent` 鼠标序列；仍无效则止损

### 2. 点击后的面板定位不到

**原因**：面板是 portal，挂在 `document.body` 下，不在字段容器内。

**解法**：从 `document` 级别找，并用可见性过滤。

```js
const panels = [...document.querySelectorAll('[class*="Dropdown"], [class*="Select-menu"], [class*="dropdown"]')]
  .filter(p => p.getBoundingClientRect().height > 0);
```

### 3. 面板会自动关闭

部分组件在选择一项后立即关闭面板，导致"选省份 → 选城市"的连续操作断掉。

**解法**：每一步之间**重新点开**，并把选择结果写进判断条件：

```js
async function cascade(labels) {
  for (const label of labels) {
    const opened = await ensurePanelOpen();   // 若已关则重新点开
    if (!opened) break;
    await clickOption(label);
    await sleep(1200);
  }
  await clickText('确定');
}
```

### 4. 值写入了但不渲染

**现象**：`input.value` 有值，但页面上显示为空，`innerText` 里没有。

**处理**：
- 以 `input.value` 为准（表单提交通常读 `value`）
- 校验不报错就继续
- **在交给用户提交前明确提醒**："这一栏显示为空但值已写入，请在预览页留意"

### 5. 只能投递 N 个职位的限制

部分校招项目限定投递数量（如"只能投 1 个"、"最多投 3 个"、"1 个月内 4 个"）。

**纪律**：
- 投递前**先确认这个项目投几个、还剩几个名额**
- 名额为 1 时，**把该平台所有可投岗位列出来对比后再决定投哪个**
- 一旦选定就不能改（部分平台 HR 处理前可换）

**确认方法**：投递按钮附近通常有提示文案，如「允许 1 个月内投递 4 个职位，还可投递 2 个」。

### 6. 登录方式决定预填什么

| 登录方式 | Agent 预填 | 人做 |
|---|---|---|
| 手机 + 短信 | 手机号、协议框 | 获取验证码 + 填码 |
| 手机 + 身份证 + 短信 | 手机号、证件号、协议框 | 图形验证码 + 短信码 |
| 手机 + 图形验证码 + 短信 | 手机号、协议框 | **图形验证码** + 短信码 |
| 微信扫码 | 协议框 | 扫码 |

**图形验证码一律不识别** —— 这是平台确认"屏幕前是人"的机制，属于设计约束。
