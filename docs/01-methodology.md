# 核心方法论

![端到端工作流](../assets/workflow.png)

> 这套方法是 60+ 家真实投递打磨出来的。每一条背后都有一次具体的翻车。

## 一、人机分工协议

这是整套 SOP 的地基。越早接受它，效率越高。

### 交接点 1：登录

**遇到登录墙 → 立刻停下，把页面准备好，交给人。**

Agent 在交接前应该完成的准备工作：

| 平台登录方式 | Agent 预填 | 人做什么 |
|---|---|---|
| 手机号 + 短信验证码 | 手机号、勾选隐私协议 | 图形验证码 + 获取验证码 + 填码 + 点登录 |
| 微信扫码 | 勾选隐私协议 | 扫码 |
| 手机号 + 身份证 + 短信 | 手机号、证件号、勾选协议 | 图形验证码 + 短信码 |

**不要尝试识别或绕过图形验证码。** 它存在的意义就是确认屏幕前是人。

### 交接点 2：最终提交

Agent 可以一路做到「预览页无缺项」，但**不能点最终的「确认提交」「提交简历」**。

原因很简单：投递是不可逆的对外行为。有些平台一旦提交就不能撤回或换岗位（例如有的大厂校招项目明确写「HR 处理前可换职位，处理后不可换」）。这个决定的后果由求职者本人承担，所以按钮也应该由本人按。

## 二、筛岗纪律

### 硬性否决（不满足直接跳过，不浪费时间）

1. **限硕士 / 限博士** → 跳过
2. **工作地点不含目标城市** → 跳过，但**必须到站点核实**

> ⚠️ **汇总表格里的城市数据经常是错的。** 实战中遇到过：某公司汇总表标"杭州"，实际打开站点城市筛选里根本没有杭州；某公司标的"产品岗是杭州"，实际全在合肥。**城市和岗位必须到站点核实，不要信二手表格。**

### 识别"岗位类别 ≠ 岗位名称"

很多招聘公告里写的「产品类」是**招聘类别**（按职能打包的一批岗位），不是具体岗位名。真正的岗位名要点进去看。

### 核实顺序

1. 打开职位列表页
2. 用站点自己的筛选器（城市 + 职能类别）
3. 看实际岗位名和地点
4. 只有"城市对 + 岗位名对 + 学历对"三者都满足才进入投递

## 三、校验驱动法

> 填完一版表单后，**不要自己去猜缺什么**。让表单的校验器告诉你。

### 做法

1. 把能填的都填了
2. 点「预览并提交」/「预览」/「下一步」（**绝不点"确认提交"**）
3. 真实校验会跑起来，把所有缺项标红
4. 收集全部红字 → 得到精确的缺项清单
5. 逐项修复 → 重复

### 收集红字的代码

```js
const missing = [];
const seen = new Set();
[...document.querySelectorAll('*')]
  .filter(e => e.innerText?.trim() === '必填项未填写')   // 按平台调整文案
  .forEach(e => {
    let p = e, ctx = '';
    for (let k = 0; k < 7 && p; k++) {
      p = p.parentElement;
      const t = p?.innerText.replace(/\n/g, '|');
      if (t && t.length < 170) { ctx = t; break; }
    }
    if (ctx && !seen.has(ctx)) { seen.add(ctx); missing.push(ctx); }
  });
return missing;   // ["证件号码|必填项未填写", "性别|必填项未填写", ...]
```

比对着 DOM 猜缺项快一个数量级，而且不会漏。

### 失焦后再看一遍

有些平台的错误提示是**渲染残留**：值其实已经写进去了，但红字要等失焦/重渲染才消失。所以：

- 填完一个字段 → 点一下页面空白处 → 再看红字还在不在
- 不要看到红字就重复填，可能已经把正确的值覆盖掉了

## 四、止损红线

> **单个字段尝试超过 4 种方法 → 立即停止，转人工。**

网申里总有几个字段是程序化填不进去的：日期穿梭框、三级级联选择器、只读输入、被虚拟列表卸载的控件。继续死磕的期望收益是负的。

### 转人工时给什么

一份**精确的手填清单**，包含：

1. 字段名（页面上显示的名字）
2. 应该填什么值（从用户资料里取）
3. 位置提示（哪个区块）

例：

```
还差 3 项，请你手填：
1. 教育经历 → 学院名称：XX学院
2. 实习经历① 某某科技有限公司 → 起止时间：2026-03 至 2026-06
3. 项目经历 Mago → 起止时间：2026-03 至 至今
```

**不要只说"有几个字段填不进去"，用户会不知道该填什么。**

## 五、简历解析结果核对清单

上传简历后，平台会自动解析并填充表单。**这一步能省 80% 的工作量，但必须先核对再继续。**

解析器的高频错误（全部来自实战）：

| 错误类型 | 现象 | 为什么会这样 |
|---|---|---|
| **专业识别错** | 明明是 A 专业，被填成完全不相关的 B 专业 | 解析器用的是关键词匹配，遇到非主流专业名会瞎猜 |
| **创业项目塞进"工作经历"** | 联合创始人经历被当成正式工作 | 解析器分不清创业和就业 |
| **公司/职位写反** | 公司名栏填了职位名 | 版面识别错位 |
| **职位名混进部门名** | "AI产品实习生/营销事业部（账号代运营组）" | 相邻文本块被合并 |
| **实习时间段串行** | 3 段实习变成 2 段，时间对不上 | 时间字段解析漏项 |
| **"是否有工作经历"被勾否** | 明明填了经历，勾选框却是"没有工作经历" | 默认值 + 解析失败 |

### 核对动作

```js
// 逐条列出实习/项目的字段值，人工扫一遍
const entries = [...document.querySelectorAll('[data-cy*="internship"], [class*="apply-fields-"]')]
  .map(g => ({
    company: g.querySelector('[placeholder*="公司"], [class*="company"] input')?.value,
    title:   g.querySelector('[placeholder*="职位"], [class*="title"] input')?.value,
    period:  g.innerText.replace(/\n/g, '|').match(/\d{4}-\d{2}.*/)?.[0],
  }));
```

## 六、长文本规则

**实习工作职责、项目描述必须用简历原文的完整版（180–500 字，含数字），不许压缩成一句话。**

原因：这些文本是 HR 和面试官真正会读的内容。压缩后信息密度骤降，"做了什么、做成了什么"就看不见了。

### 长度参考

| 字段 | 建议长度 |
|---|---|
| 实习工作职责 | 200–350 字 |
| 项目描述 | 250–450 字 |
| 自我评价 | 250–400 字 |
| 开放性问题 | 500–800 字 |

### 注意 maxlength

先探测字段的 `maxlength` 再决定填哪个版本：

```js
document.querySelector(selector)?.maxLength   // -1 表示无限制
```

## 七、数字归属的诚实原则

简历和表单里的量化结果，**必须写清是个人成果还是团队盘子**。

反面写法：
> "把下单转化率从 30.2% 提到 37.5%，单月增量 GMV 约 1200 万"

正面写法：
> "把下单转化率从 30.2% 提到 37.5%（团队盘子对应单月增量 GMV 约 1200 万元）"

这不是道德说教，是风控：面试官一旦追问"这 1200 万是你一个人做的？"，答不上来就是致命的。**把归属写清楚，既经得起追问，也更容易被信任。**

## 八、台账纪律

见 [`04-data-management.md`](04-data-management.md)。三条底线：

1. **一家投完才记一家**，不要批量补记
2. **写数据前先算好目标行号**，不要用固定行号
3. **写完校验序号连续性**，发现缺口立刻排查

## 九、效率数据

用这套方法的实测数据（60+ 家投递）：

| 环节 | 纯手工 | Agent 辅助 |
|---|---|---|
| 筛一家公司（找岗 + 核岗） | 5–15 分钟 | 2–5 分钟 |
| 填一份完整表单 | 20–40 分钟 | 5–15 分钟（含人工登录与手填） |
| 记录台账 | 3–5 分钟 | 自动化 |

**真正的瓶颈从来不是填表速度，而是筛岗准确率。** 一个填得再快的表单，如果岗位本身不合适，就是纯浪费。所以这套 SOP 里筛岗纪律占的分量最重。
